PRISM ARCHITECTURE SUMMARY (REUSABLE PROMPT CONTEXT)
====================================================

Project Shape
-------------
- Core loop and app framework live in src/shared.
- Platform abstraction is in src/platform/*.h.
- Concrete platform implementations:
  - RP2040 target: src/rp2/*
  - Host target: src/host/*
- Build chooses host vs rp2 in CMakeLists.txt via PICO_PLATFORM.

Timing Model
------------
- Tick rate: 1000 Hz (TICK_RATE=1000) -> 1 tick ~= 1 ms.
- Frame rate target: 120 FPS.
- Engine tracks both:
  - g_engine.tick: uint32 tick counter (ms-like game clock)
  - g_engine.now: platform time in microseconds
- Main loop (engine_run_forever):
  1) Calls platform_task() every loop
  2) Catches up all due ticks first
  3) Draws at most one frame when due

App Lifecycle (app_t)
---------------------
Each app can implement:
- enter(): called when app becomes active
- tick(): simulation/update step (1000 Hz)
- frame(): render step (target 120 FPS)
- pause(): called when menu/sleep pauses app
- resume(): called when app resumes
- leave(): called before switching away

App switch behavior (engine_set_app):
- Calls old app leave()
- Clears system animations
- Resets button state
- Defaults to launcher app if NULL
- Resets tick counter
- Resets synth voices (panic + reset)
- Seeds RNG from platform time
- Calls new app enter()

Input and Button Semantics
--------------------------
Button API:
- BUTTON_KEYDOWN(id): pressed && edge
- BUTTON_KEYUP(id): !pressed && edge
- BUTTON_PRESSED(id): pressed state
- engine_button_held_ratio(id): hold progress 0..1
  - trigger at ~300 ms
  - confirm at ~1200 ms

Critical edge timing rule:
- If an app implements tick(), left/right edge flags are cleared immediately after tick().
- If an app does NOT implement tick(), edges survive until frame() clears them.
- Therefore:
  - Apps with tick(): consume KEYDOWN/KEYUP in tick() for reliability.
  - Apps without tick(): consuming KEY* in frame() can work (launcher pattern).

engine_buttons_reset() behavior:
- Forces left/right to pressed=false and ignore=true.
- Future presses are ignored until next release event clears ignore.
- Use for transitions/debouncing, not as a general per-screen entry default.

Menu/Pause Architecture
-----------------------
- Menu is engine-level UI drawn in engine.c (menu_frame).
- Menu opens via MENU key, pauses app via engine_pause().
- While paused:
  - app tick/frame are skipped
  - menu handles navigation, hold-confirm, and volume changes
- engine_resume() returns control to app and unpauses animation system.

Rendering and UI Stack
----------------------
- Display is 128x64 monochrome u8g2.
- frame() should draw into u8g2 buffer only.
- Engine sends display buffer after app frame/menu frame.
- Utility UI layer: src/shared/utils/elm.h
  - hierarchical layout helpers
  - basic primitives, text, rounded frames/boxes, button helper, qr helper

LED Model
---------
- Two LEDs: LED_L and LED_R.
- Engine clears LED colors at start of every frame.
- App/menu set desired LED colors each frame.
- Engine flushes LEDs at end of frame.

Audio Architecture
------------------
- Shared FM synth in src/shared/audio/synth.*
  - 8 voices, 4 operators per voice
  - queue-based message interface for note on/off/panic
- Song sequencer in src/shared/audio/song.*
  - timed event playback (NOTE_ON/OFF, PATCH, MARKER, etc.)
  - driven by audio_song_player_tick(player, now_ms)
- RP2040 runs playback loop on core1 (see src/rp2/main.c).
- Engine owns synth instance at g_engine.synth.

Platform Abstraction Contract
-----------------------------
Core platform calls:
- platform_init()
- platform_task()
- platform_now_us(), sleep helpers
- platform_input_read_mask()
- platform_display_get_u8g2(), display enable
- platform_leds_show()
- platform_peripheral_* (power/battery/charging)
- platform_watchdog_* and platform_system_reset()
- platform_sleep_enter()
- platform_mutex/queue wrappers in platform/sync.h

Adding a New App (practical checklist)
--------------------------------------
1) Create app source file under src/shared/apps/<app>/app.c with app_t definition.
2) Export app symbol in src/shared/apps/apps.h (extern app_t app_<name>;).
3) Add app source(s) to SHARED_SOURCES in CMakeLists.txt.
4) Add app pointer to launcher app list in src/shared/apps/_launcher/app.c.
5) If app uses hold+tap controls and also has tick(), process button edges in tick().
6) For full reset on start/new run, initialize your app state in enter().

Beatline-Specific Lessons Worth Reusing
---------------------------------------
- With both tick() and frame() present, KEYUP handling in frame() can silently fail.
- Move input edge processing to tick() to match engine edge lifetime.
- Keep frame() mostly rendering and visual-only state updates.

Prompt Template For Future Feature Work
---------------------------------------
Use this in future prompts:

"Project architecture constraints:
- App lifecycle: enter/tick/frame/pause/resume/leave (tick=1000Hz, frame~120FPS).
- If app has tick(), button KEYDOWN/KEYUP should be handled in tick(), not frame(), because button edges are cleared after tick.
- Display is 128x64 u8g2; use elm helpers for layout.
- LED colors are reset each frame; set desired LED values every frame.
- Platform APIs are abstracted through src/platform/*.h and implemented in src/rp2 or src/host.
- Integrate new apps by updating apps.h, CMake SHARED_SOURCES, and launcher app list.
Please follow existing coding style and keep changes minimal and targeted."
